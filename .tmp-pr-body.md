## Why This Matters

Today, apps can only browse their own `wiki/` folder. With this PR:
1. **Any app** (planet, myplanet, future projects) can register a tenant → store SDDs in PromptRoot's Firestore
2. **Agents** (Claude Code, Cursor, Continue, Cline) can search, create, and update SDDs without leaving the editor
3. **No per-repo clutter** — no more `wiki/`, `scripts/build-wiki-index.js`, `.github/workflows/wiki-index.yml` in every repo
4. **Single source of truth** — SDDs live in Firestore with version history, not scattered across git logs
5. **Device-flow auth** — same GitHub identity as the web app; no PATs, no separate credential lifecycle

## Architecture Highlights

- **Firestore rules gate visibility** — public tenants queryable by anyone; private only by members. All writes via Cloud Functions (admin SDK).
- **Session tokens** (`prs_`-prefixed) distinguish from Firebase ID tokens; `resolveBearer` routes correctly.
- **Non-destructive versioning** — restore writes a new snapshot, preserving full history.
- **Cross-platform credential storage** — `~/.config/promptroot` on Unix, `%APPDATA%\promptroot` on Windows.
- **Tenant resolution** — explicit arg → `.promptroot-tenant` file → git remote lookup → error (graceful fallback).

## Bugs Fixed (post-review hardening)

1. **`functions/lib/` shared CJS files (deploy-blocking)** — `wiki.js`, `wiki-chunks.js`, and `rag.js` were requiring from `../scripts/lib/` which is outside the `functions/` source directory that Firebase uploads. Added `functions/lib/{chunker,sdd-validate,tokenizer}.cjs` (copies of the canonical `scripts/lib/` originals) and updated all require paths. Without this the new Cloud Functions would fail at cold-start with module-not-found.

2. **`auth-device-page.js` user-code regex (UX bug)** — client regex allowed `I`, `O`, `0`, `1` which the server's `USER_CODE_ALPHABET` deliberately excludes. Real users typing ambiguous characters would receive "Invalid or already-used code" from the server. Tightened the regex to `[A-HJ-NP-Z2-9]` and updated the input sanitizer to strip those characters as the user types.

3. **`pollDeviceAuth` silent status fallthrough** — any non-`authorized` status (including malformed/corrupted documents) was returning `pending` indefinitely. Now logs and returns 500 on unexpected states so the CLI can surface a real error instead of polling forever.
